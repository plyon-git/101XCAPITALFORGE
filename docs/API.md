# CapitalForge API

The browser and API run on the same origin. All API results are JSON except file downloads. There are no outbound email or SMS integrations. A task or stage change records internal work only.

## Authentication

`GET /api/status` returns `setup_required`, `user`, `csrf`, `name` and `version`. `user` and `csrf` are null when signed out.

`POST /api/setup` accepts `{name,email,password}` and creates the first administrator only. Use localhost before deploying. The password must contain 12 to 1,024 characters. External setup requires a separately configured `CAPITALFORGE_BOOTSTRAP_TOKEN` and matching `bootstrap_token` body field. A request arriving from a local reverse proxy but addressed to a public hostname is treated as external.

`POST /api/login` accepts `{email,password}`. Successful setup/login returns `{user,csrf}` and sets an HttpOnly, SameSite=Strict cookie. Passwords use PBKDF2-SHA256 with 600,000 iterations and individual random salts. Sessions last 12 hours. `GET /api/me` returns `{user,csrf}`. `POST /api/logout` revokes the current session.

Every write except setup/login requires the session cookie and `X-CSRF-Token`. Set `Content-Type: application/json` for JSON bodies. Empty DELETE/POST bodies are supported. Cross-origin writes are rejected. Failed logins are limited to 15 attempts per connecting IP in 15 minutes; a local reverse proxy shares its limit among users. Authentication and contact data are excluded from application access logs.

## Roles

| Operation | Viewer | Analyst | Administrator |
|---|---|---|---|
| Read/export contacts, deal, tasks and team names | Yes | Yes | Yes |
| Create/edit/import contacts, notes and tasks | No | Yes | Yes |
| Delete contact | No | No | Yes |
| Manage users, deal, audit and backups | No | No | Yes |

An analyst may delete tasks. Team email addresses are shown only to administrators. Removing the last active administrator is prohibited. Password, role or active-status changes revoke that user's sessions.

## Contacts

`GET /api/leads` returns `{items,total,limit,offset}`. Pagination defaults to 50, maximum 500. Supported filters: `q`, `stage`, `fit` (single or comma-separated), `state`, `capital_verification`, `verification_status`, `lender_type`, `do_not_contact=0|1`, `contact_complete=1`, `capital_min=<number>`. `sort` accepts `company`, `updated_at`, `created_at`, `id` or `state`. The text search matches company, contact name, email, phone, state and lender type; wildcard characters are treated literally.

`POST /api/leads` creates one lead; `GET /api/leads/:id` returns the lead with `notes` and `tasks` arrays. `PATCH /api/leads/:id` updates provided fields. `DELETE /api/leads/:id` is administrator-only and removes attached tasks and notes; an audit record remains. Prefer suppression for routine outreach exclusion.

| Field | Type / accepted values |
|---|---|
| `company`, `name` | String; at least one is required |
| `email`, `phone`, `website`, `city`, `state` | Public business contact/location fields; empty values allowed |
| `lender_type`, `financing_types`, `collateral_requirement` | Descriptive strings; organization type and financing suitability must remain distinct |
| `min_check`, `max_check`, `cash_capacity` | Nonnegative number or null; do not infer personal liquidity from fund assets |
| `capital_verification` | `unverified`, `stated`, `documented` |
| `fit` | `unreviewed`, `potential`, `strong`, `poor` |
| `fit_reason`, `evidence` | Evidence and reasoning strings |
| `stage` | `new`, `reviewing`, `qualified`, `contacted`, `due_diligence`, `terms`, `closed`, `passed` |
| `do_not_contact` | Boolean, preserved when future imports duplicate a suppressed contact |
| `source_url`, `source_title`, `source_date` | Primary source URL/title/date |
| `verification_status` | `unverified`, `source_observed`, `verified`; source-observed is not independently verified capacity |
| `sources` | Additional source objects array |
| `tags` | Array of tags |
| `metadata` | Object preserving additional source fields, up to 100,000 characters |
| `owner_id` | User ID or null |

IDs and timestamps are generated by the CRM. Unknown imported fields are preserved under `metadata`. Recognized import aliases include `company_name`, `business_name`, `contact_name`, `contact_email`, `phone_number`, `contact_phone`, `source`, `capacity`, `capital_verification_status`, `contact_status` and `fit_status`.

`POST /api/import` accepts `{rows:[...]}` or `{csv:"company,email,...\n..."}`, up to 25,000 records and 20 MB per request. It returns `{inserted,merged,invalid,errors}`. The first 30 errors include row numbers. Deduplication uses normalized email, then company/website identity, or company/contact/phone identity when email is absent. Duplicate imports fill blank fields and retain additional provenance; they preserve current stages, fit reviews, ownership, capital status and suppression. Ambiguous name/domain variants should still receive a human duplicate review.

`GET /api/export.csv` and `/api/export.json` accept the same filters as the contact list and export all matching records. CSV cells that could be interpreted as spreadsheet formulas are prefixed with an apostrophe. JSON retains original text. Export actions are audited.

## Notes and tasks

`GET /api/leads/:id/notes` returns `{items,total}`; `POST` accepts `{body}`. Note text is limited to 20,000 characters. Notes record author and creation time.

`GET /api/tasks` returns `{items,total}`, with pagination and `status`, `lead_id`, `assigned_to` filters. `POST /api/tasks` accepts `{title,lead_id?,due_date?,status?,assigned_to?}`. `PATCH /api/tasks/:id` updates those fields; `DELETE` removes the task. Task status is `open`, `done` or `cancelled`; due dates use YYYY-MM-DD. `GET/POST /api/leads/:id/tasks` also works.

## Dashboard and deal

`GET /api/stats` returns total contacts, `with_email`, `with_phone`, `contact_complete`, `suppressed`, `capital_documented_minimum`, `potentially_suitable`, `confirmed_suitable`, `open_tasks`, `overdue_tasks`, `sources`, `by_stage`, `by_fit`, `by_state`, `by_capital_verification` and `by_verification_status`.

`capital_documented_minimum` counts rows explicitly marked documented with cash capacity at least $500,000. `confirmed_suitable` also requires `fit=strong`, absence of suppression and a collateral description compatible with this opportunity. `potentially_suitable` counts unsuppressed potential/strong rows except descriptions clearly requiring a property lien. These are internal research states and must be supported by the attached evidence; the CRM does not independently verify representations or underwriting.

`GET /api/deal` returns the current opportunity. Administrator-only `PATCH /api/deal` updates recognized fields. Initial values are user-supplied estimates and proposals: $100,000–$500,000 raise, 50% target total return over 6–12 months, 9.3% equity alternative for $500,000, a 500-property fulfillment objective in 60 days, $5 million estimated initial fees and $115 million contemplated follow-on tied to the 450th submission. The $2.2 billion counterparty description is unverified. `terms_status` carries those qualifications.

## Administration

`GET /api/users` returns `{items,total}`. Administrator-only `POST /api/users` accepts `{name,email,password,role}`. `PATCH /api/users/:id` accepts `name`, `role`, `active` and/or `password`. Users are disabled rather than deleted.

Administrator-only `GET /api/audit` returns `{items,total}` with pagination, including actor, action, entity and nonsecret detail. It records setup/auth events, imports, changes, exports, password recovery and snapshots.

Administrator-only `POST /api/backup` returns `{filename,created_at,download_url}`. The returned `/api/backups/<filename>` URL downloads a consistent SQLite snapshot. Live sessions and login-failure history are removed from snapshots; password hashes and contact data remain. The database is not publicly served.

HTTP errors return `{error:"message"}`. Expected codes include 400 invalid inputs, 401 sign-in required, 403 unauthorized role/CSRF/origin/host, 404 not found, 409 duplicate/constraint conflict, 413 oversized body, 415 unsupported body format and 429 login throttling.
